What failure mode was addressed:
Reading `Parcelable` data from an `Intent` provided by an external application via Android's share sheet (`ACTION_SEND` and `ACTION_SEND_MULTIPLE`) can cause severe app crashes (e.g., `BadParcelableException` or `ClassCastException`) if the sender provides malformed data or if there's a classloader mismatch.

What changed:
Wrapped `intent.getParcelableExtra` and `intent.getParcelableArrayListExtra` calls inside robust `try-catch` blocks within `MainActivity.kt`. If extraction fails, they safely return `null` instead of crashing the activity.

Why the fix is low-risk:
The downstream logic already correctly handles `null` values using safe-call (`?.let`) blocks. The "happy path" remains functionally identical, and there are no architecture or dependency changes.

How it was validated:
- Local verification with `./gradlew :androidApp:compileDebugKotlin` and `./gradlew :composeApp:compileKotlinJvm`.
- Code review explicitly confirmed correct functionality and no regressions.
