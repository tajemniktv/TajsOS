# Changelog

All notable changes to TajsOS should be documented in this file.

This project does not promise strict Semantic Versioning guarantees yet, because the product is still highly experimental.
Still, release notes should stay clear, structured, and honest.

## Format

Each release section should generally include:
- Added
- Changed
- Fixed
- Removed
- Docs
- Internal

Not every release needs every section.

## Release notes philosophy

Good changelog entries should:
- describe user-visible impact first,
- avoid commit-message spam,
- group related changes,
- mention important breaking or behavioral changes clearly.

Bad changelog entries usually look like:
- “misc fixes”
- “stuff”
- giant raw dump of internal commits
- fake marketing language hiding what changed
