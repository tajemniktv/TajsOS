## Current conclusion and adoption order

Keep the KMP/Compose foundation, local Room/DataStore persistence, manual wiring, connected life-object model, typed companions and existing shared item identity. Do not infer a need for a rewrite, microservices, event sourcing, universal block database, or a second organizer per domain. Android and Desktop remain the active product focus; iOS and web application targets must not be described as equally verified.

The biggest change since the DOCX is that full **Room-table** backups, token redaction, transaction-wrapped aggregate writes, failed calendar-fetch preservation, repeated triage/pin/completion guards, nullable facet clearing and schedule preservation on unrelated edits now exist. This does **not** make an export a portable whole-profile archive: attachment bytes, Android URI grants, DataStore settings/entitlements and unrelated-database identity remapping remain outside the backup contract. Private ICS URLs can themselves be credentials, and the JSON is unencrypted. Destructive migration fallback remains enabled on all platform builders. Do not promise irreplaceable-data safety or cross-device merge on the strength of the repaired Room snapshot alone.

Suggested dependency order, updated from both audits:

1. Decide the durability promise and close or clearly disclose destructive-upgrade, external-file/permission, private-feed-URL and cross-dataset restore limits before inviting irreplaceable data.
2. Preserve the now-tested transaction/retry/schedule invariants; add the remaining SQL uniqueness, integrity, timezone and collision tests where the contract requires them.
3. Declare field and relationship ownership, effective Project-to-Area membership, explicit domain membership, and stable public identity before expanding read models or sync.
4. Deliver one coherent capture → assign → find → complete path across core lists, Project, Area, Study/domain lenses, Dashboard and Today without copying the item.
5. Remove misleading Finance/site status claims and dead active controls, then verify accessibility, release artifacts and target support.
6. Treat production sync and product-specific connectors as conditional future work, not an implication of the Ktor prototype or calendar/share adapters.

The original priority vocabulary was **G0** data gate, **P1** foundation, **P2** product/platform readiness and **P3** deferred capability. These express consequence and dependency, not delivery dates. The table below retains the original finding IDs and priority while recording current status.

## Proposed architecture and semantics retained from the DOCX

Everything in this section is a **candidate contract**, not a current guarantee or accepted instruction. Reconcile it with canonical product docs and explicit user decisions before implementation.

### Logical boundaries and command/query shape

Avoid immediate Gradle-module proliferation. Domain values and state transitions should not depend on Compose, Room, Android or HTTP; application commands/queries depend on domain values and ports, not widgets or DAO implementations; Room/DataStore implement local ports; platform entrypoints adapt share, voice and paths; presentation calls named operations and read models; optional integration/server adapters own provider/auth/protocol details. Keep one local item identity and local-first operation. `MainViewModel` may be the first coordinator, but feature-heavy orchestration should move to bounded components as ownership becomes clear.

A proposed command targets an item or capture ID, identifies an operation/expected revision, supplies **explicit changed fields**, and returns typed success/no-op/conflict/validation result. Related facet, relation, schedule, event and inbox writes commit together. A retry reuses an operation ID; `CompleteTask` reloads current state, creates at most one recurring successor under a stable occurrence key, and reopening is a distinct transition. These are stronger future contracts than the current full-`NodeEntity` update API and must not be described as implemented. Named reads could include `TasksForProject`, `TasksForArea(effectiveArea)`, `WholeLifeNow`, `PinnedForToday(localDate)`, `StudyAssignments` and `ItemsForDomain`. Each returns the same canonical item ID with an explainable membership label; a view is not a writable copy.

### Candidate field-owner matrix

| Concern | Proposed authority | Transition caution |
| --- | --- | --- |
| Identity, title, common lifecycle | Shared item with stable public ID; local `Long` remains a join surrogate | Add public IDs only for real portability/reference needs; one writer. |
| Task state, estimate, next step, recurrence | Task facet and typed commands | Node status becomes a one-way compatibility projection, not a second writer. |
| Note flavor/source review; dated record kind/time | Note facet; Record facet | Map legacy idea/resource/vault aliases deliberately; do not silently turn Notes into Records. |
| Project/Area purpose and lifecycle | Project/Area facets | Keep finite outcome separate from ongoing responsibility. |
| Long body | Rich-content document | Node content is excerpt/legacy fallback; avoid two editors writing competing bodies. |
| Due/start/reminders/calendar | Schedule entries and typed date/time values | Legacy scalars become summaries; unrelated edits never rewrite rich time detail. |
| Project/Area/general graph | One declared authority per role | Validate kinds/endpoints and preserve unrelated edges. |
| Domain membership; tags | Explicit item-domain table; tag records plus `node_tags` join | Heuristics can suggest; labels and domain membership remain distinct. |
| Attachments/external references | Typed ref with portability and provenance | Distinguish copied bytes, private URL and device-local path/permission. |
| Raw capture | `InboxEntry` until triage | Triage + target link is atomic/idempotent; direct-create is a separately labeled path. |

For the cross-scope acceptance example, create Area **Dev**, Project **TajsTokens** in Dev, and one Task only under that Project. The suggested effective-Area rule is explicit Task Area override, otherwise inherit Project Area. Verify the same Task ID once in Project Work, Area Dev, Tasks All, Search and a declared whole-life Dashboard rule. **Today** remains an explicit pin, not a synonym for Dashboard; completion/reopen/moving Project must change projections, never clone the Task. No separate Project named Dev was found in the old source review; the example is an acceptance fixture, not seed-data truth.

### External reference and optional service model

A reference-only external link, if desired, should attach to the existing Project and record provider/source kind, display label, verified URL or device-scoped path, optional provider object ID, provenance/check state, local-device scope and declared link/read/write capability. A link is not evidence of API access; a read adapter needs verified API/auth scopes, cache/offline and revocation behavior; a write adapter needs narrow commands, visible provenance and authorization for consequential external writes. Credentials do not belong in ordinary recovery JSON. A missing/moved local path is unavailable on that device, not portable truth. No ChatGPT/Codex/Work/Library/Echo API or embedding capability was verified by either source audit.

If sync is ever chosen, keep Room as the offline source of truth and send versioned idempotent changes through a typed transport/queue. A server acknowledgement must follow a durable commit. Decide single-owner self-hosted versus account-scoped hosted operation before choosing auth and isolation. Use server-issued ordered checkpoints and explicit conflict records/revisions; client wall time is metadata, not authority. Define deletion/tombstone retention, attachment transport and device paths. This is a conditional design, not current scope or an assertion that production sync was approved.
