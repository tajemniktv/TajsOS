# TajsOS Code of Conduct

## Why this exists

TajsOS is opinionated, personal, and still evolving fast.
That usually means strong preferences, blunt feedback, and a lot of iteration.

That is fine.

What is not fine is making the repo unpleasant, unsafe, or exhausting for other people to participate in.

This code of conduct exists to keep collaboration sharp without turning it hostile.

## The standard

When participating in this project, you are expected to:
- act in good faith,
- criticize ideas without demeaning people,
- be direct without being needlessly cruel,
- respect boundaries,
- assume the project has a coherent vision even if you disagree with it,
- accept that maintainers may say “no” to changes that do not fit.

## Encouraged behavior

Good contribution behavior includes:
- bringing evidence, reasoning, and examples,
- disagreeing clearly and specifically,
- being honest about tradeoffs,
- accepting feedback without turning it into drama,
- respecting the maintainer’s final call on project direction,
- helping improve clarity, quality, and coherence.

## Unacceptable behavior

The following is not acceptable:
- harassment, threats, intimidation, or stalking
- discriminatory, hateful, or dehumanizing language
- personal attacks, insults, or humiliation
- sexualized comments or unwanted sexual attention
- deliberately inflammatory trolling
- bad-faith issue spam, PR spam, or review spam
- doxxing, privacy violations, or sharing personal information without permission
- persistent boundary-pushing after being asked to stop
- knowingly misrepresenting the project, the maintainer, or other contributors
- using AI or automation to flood the repo with low-quality noise
- hostile dogpiling, brigading, or pile-on behavior
- publishing private communications without permission, unless required for safety or law

## About tone

This project does not require fake corporate politeness.

Blunt, technical, strongly worded feedback is allowed.
Sarcasm is not automatically a violation.
Disagreement is not automatically hostility.

The line is crossed when the interaction stops being about the work and starts becoming demeaning, threatening, harassing, or deliberately toxic.

## Scope

This code of conduct applies to:
- issues
- pull requests
- discussions
- review comments
- project-linked chats or community spaces, if any
- other spaces where someone is representing the project

## Maintainer rights and responsibilities

The maintainer may:
- set and defend the project direction,
- close issues or PRs that do not fit,
- request changes,
- moderate discussions,
- remove content that violates this policy,
- block or ban repeat offenders.

The maintainer should try to:
- explain rejections when reasonable,
- stay consistent,
- avoid wasting contributors’ time,
- enforce rules based on behavior, not vibes.

## Enforcement

If someone violates this code of conduct, the maintainer may take any action considered appropriate, including:
- asking for a correction,
- deleting comments,
- locking conversations,
- closing issues or PRs,
- limiting interaction,
- temporary ban,
- permanent ban.

Not every action requires a warning first.

## Final note

TajsOS can be intense, opinionated, and experimental.
That is part of the appeal.

The goal here is not sterile politeness.
The goal is a space where people can contribute without getting treated like shit.
