# Support

## What this file is for

Use this guide to figure out where to ask what.

## Bug reports

Open a GitHub issue if:
- something is broken,
- behavior is inconsistent,
- the app crashes,
- data appears wrong,
- documentation is clearly out of sync with the repo.

Please include:
- what happened,
- what you expected,
- steps to reproduce,
- platform,
- logs / screenshots if relevant.

## Feature requests

Open a GitHub issue if:
- you have a feature idea,
- you want to propose a UX improvement,
- you want to discuss a direction before building it.

The best feature requests explain:
- the actual user problem,
- why the current system is insufficient,
- why the idea fits TajsOS specifically,
- tradeoffs and scope.

## Security issues

Do **not** open public issues for sensitive vulnerabilities.
See `SECURITY.md`.

## Questions

If you are unsure whether something is a bug, feature request, or design discussion, open an issue and label the uncertainty clearly.

## A note on support expectations

TajsOS is currently a solo, experimental project.
That means:
- support is best-effort,
- replies may not be instant,
- not every request will get implemented,
- a cleanly explained issue has a much better chance than “doesn’t work”.

## Before opening an issue

Please check:
- `README.md`
- `CONTRIBUTING.md`
- `ARCHITECTURE.md`
- existing issues

That saves everyone time.
